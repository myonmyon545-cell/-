## iPadで開始する

AI実行指示.mdをプロジェクトの情報源へ追加し、00/10/20/30の4チャットを開く。それぞれROLEと「該当startupを実行」を送る。まず00と10を開始。ユーザーによるターミナル操作は不要。各AIが接続済みGitHubを使って同じ確定コミットのPLANとSTATEを読む。

10→20→00。指摘があれば20→30→10→20→00。各担当は自分の報告を更新し、00がSTATEを統合する。GitHubに置くだけで別チャットは起動しない。次の担当にはユーザーが短い開始指示を送る。

## 再評価を速くする

最初の候補は全独立評価。その後も全指標の機械検査は毎回実行し、独立AI評価は変更指標と依存する比較・説明・グラフへ集中する。C03/C04は再確認。入力・定義・コード・テンプレート・計画版が変わったら評価を再利用しない。20は再利用した検査の元候補と元評価コミットを報告に残す。

候補ID・保存版・Excelハッシュ・検査JSONのfingerprintを20が固定する。候補JSONと10の報告は同じコミットで更新。競合時は読み直し、強制上書きしない。

## 軽量検査

Actions → Care handoff checks で実行結果を確認する。対象フォルダ更新時に起動し、手動起動もできる。読取り権限のみ、追加APIキーなし、定期起動なし。候補Excelは取得しないため、Excelの表示や出所の独立評価は20が行う。初期のmetadata PASSは本解析合格を意味しない。

Actionsが利用できない場合は10が次を実行し、同じ版付き結果を報告する。

```bash
python3 -m unittest discover -s care-insurance-analysis/tools -p 'test_*.py' -v
python3 care-insurance-analysis/tools/verify_handoff.py
```

原本Excel/PDF・個票・認証情報は登録しない。GitHubが読めないチャットには確定コミットの必要資料を添付し、00が正本へ反映する。Drive/Airtableへ同じ進捗を増やさない。
